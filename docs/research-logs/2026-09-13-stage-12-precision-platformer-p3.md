## 3. Reconciliation and boundaries

| Relationship / possible conflict | Resolution and consequence |
|---|---|
| Swink response curves versus an assumed ideal of instant movement | Preserve the game's chosen response. Measure mapping and perceptible onset separately; no universal “make it snappier” rule |
| Totten metrics-first language versus Adams/Dormans allowing space-first design | Treat the movement/space relationship as an iterative constraint. A pre-existing authored room is allowed; establish whether the chosen movement actually supports it before approval or replication |
| Mechanic predictability versus Adams/Dormans's preference for unpredictable games | Local declared input/contact behaviour can be predictable while execution, decisions or interactions produce uncertain outcomes. Do not randomise controls to manufacture depth |
| Fullerton controlled tests versus natural traversal / first-use evidence | Use both for their questions. A privileged start reduces diagnostic cost but can remove the approach, knowledge or pressure that caused the complaint; record that limitation |
| Lemarchand late-change restrictions versus material correction | Preserve authority and dependency review already owned by core. Milestone terminology cannot forbid correction of a serious issue; coordinated changes need a reason and affected-case checks |
| Swink feedback and Totten repeated cues | Merge around usable event information in context. Extra sound/effects or visual repetition alone do not prove comprehension or access; hand off craft to adjacent domains |
| Fullerton and Lemarchand playcentric overlap | L1 explicitly depends on Fullerton, so repetition is not independent evidence. Fullerton supports question/observation choice; Lemarchand adds representative integration and change-impact context. General testing/scoping instructions stay core |

**Core:** authority, evidence provenance, accessible task coverage, mechanic specification, prototype adequacy, content contracts, testing and small repair. **Pack:** recurring movement-envelope, contact-order, landing/view, route-dependency and focused-attempt questions connected into one workflow. **Project:** actual units, speed/acceleration/jump rules, tolerance durations if any, geometry, camera, audience, supported inputs and difficulty intent. No book creates a mandatory dash, moving platform, economy, generator, assist setting or art style.

## 4. Provisional model and P4 questions

The provisional workflow is: establish the declared movement/input model; measure it in an executable sandbox; relate spatial demand and information to those measurements; exercise boundary and repeated-attempt cases; inspect human traversal for comprehension/experience claims; localise a correction and recheck affected accepted routes. Stages can iterate when an existing level or approved controller is the starting point.

P4 must now challenge: when tolerance/buffering helps or harms the intended execution; whether immediate retries are always desirable; how motor/temporal access changes demand without silently changing accepted identity; when automated routes fail to represent actual inputs/timing; and how cue information competes with effects. No universal numeric threshold, enjoyment claim or causal explanation for a commercial game's success has been accepted.

The proposed cases extend existing core questions BC05 (boundary input), BC06 (content replacement), BC07 (unrecognised danger), BC11 (jump change breaks route) and BC12 (built/restarted behaviour). These reference the original candidate cases; none is claimed as executed here. P5 will define exact pack acceptance cases after challenge research.
