## 4. Domain authoring and packaging decisions

The new contract extends `game-extension-pack-creator` / `author-extension-pack`, preserving Stage 11's three-skill boundary and named operations. It defines qualification, profile semantics, source permissions/reuse, separate research gates, explicit selection/precedence, local loading, P6/P7 production/comparison/reuse/install proof and migration. No second generic authoring system or mandatory P-stage runtime commands are added.

Select packs through ordinary project/user instructions. Bundle required optional profiles in each independent consuming skill's own `references/packs/` with a local index; load only explicitly selected relevant guidance. Core remains useful alone. Installed use cannot require the creator, another pack, sibling skill, source books, research logs or central checkout. Repeated necessary invariants across independent consumers are acceptable; bulk research duplication and a shared runtime are not justified.

P7 uses identical substantive prompts and comparable resources, with exact context/revision and actual outcome records. It tests behaviour, defects, preservation and reuse rather than metadata or prompt length. Negative and inconclusive outcomes remain visible. The contract does not guarantee readiness or general superiority; useful specialist effect and clean installed use still need real evidence.
