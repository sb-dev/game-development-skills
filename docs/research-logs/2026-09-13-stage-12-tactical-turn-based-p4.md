## 2. Material claim dispositions

The final-column rules are this project's evidence-qualified adaptations. Original book dependence and standing remain visible in P3.

| Claim / P3 coverage | Support, counterexample, alternative or failure condition | Evidential standing | Disposition / production consequence |
|---|---|---|---|
| Every action needs a certain-outcome preview (TTF-04, 08, 10) | TTS-01 demonstrates advance attack information; TTS-02 exposes chance and concealment | Different documented game rules, no universal winner | **Reject certainty as a default; retain truthful decision information.** State what is known, conditional or hidden. Preview must match its declared scope and must not disclose withheld state |
| Action budgets or equal expected damage prove tactical balance (TTF-01–03, 07, 09) | TTS-03's contextual/conditional valuation and TTS-02's terrain/range effects challenge one-number comparison | Context-dependent analytic method | **Qualify.** Check opportunity, position, objective and relevant alternatives in actual encounters. A mathematically equal effect may still have a different tactical role |
| A fitted cost curve is a universal content-generation gate (TTF-01, 09) | TTS-03's uncertain derivation and new-game limitations conflict with its strongest guarantees | Useful practitioner heuristic; universal sufficiency unsupported | **Reject guarantee; retain bounded hypothesis.** Keep assumptions, accepted traits and test coverage explicit. Do not invent exchange rates to force every mechanic onto one score |
| Two scripted strategies establish depth or fairness (TTF-02, 10, 12) | P3 model limits; TTS-01/02 show distinct information/objective conditions a script could omit | Bounded technical evidence; human/strategic generalisation unresolved | **Reject sufficiency.** Declare policy, available knowledge, starting cases and randomness. Repair invalid strategy coverage or evidence before changing accepted costs; use appropriate humans for decision-quality claims |
| Local turn-based execution cannot have delayed-state faults (TTF-04–06, 11) | TTS-04 separates current jobs from later callbacks; a restart or new selection can happen between them | Documented execution behaviour; concrete failure is a test hypothesis | **Extend cases.** Delayed presentation/opponent callbacks must respect the current session/phase. Test restart during resolution and a changed target; no stale job may mutate the new encounter |
| A state machine / command object guarantees single resolution (TTF-04–06) | Nystrom's own caveats plus TTS-04: implementation forms do not encode all game-level prerequisites | Unsupported guarantee | **Reject.** Validate the actual eligible actor, action, cost and phase at commitment. Repeated or stale confirmations must produce the declared effect count and no partial illegal spend |
| Incidental unit-list order is acceptable initiative (TTF-05–06, 11) | P3 order-dependence analysis and the game's declared phase contract | Technical/design constraint | **Reject hidden order.** Sequential initiative is valid when declared; simultaneous phases need their own observation/collision rules. Permute storage order only where the game promises order independence |
| Every tactical action should be undoable (TTF-04, 10) | Nystrom offers undo as a feature; TTS-02 distinguishes recovery preferences and player choice | Contextual feature / production preference | **Qualify.** Specify selection cancellation, committed undo, restart and any information/randomness consequences separately. Neither a missing optional undo nor a chosen strict commitment is automatically a defect |
| Untimed turns make the game accessible (TTF-08, 10) | TTS-05–08 add navigation, focus, cue and UI timing responsibilities | Specialist guidance; game-specific adequacy unproved | **Reject sufficiency.** Check the full selection → preview → cancel/commit → outcome → restart path using declared input alternatives and visible focus; turn pacing alone cannot pass access review |
| Spatial appearance establishes protection or legality (TTF-03, 07–08) | TTS-02's rule-dependent movement and combat support Totten's contextual qualification | Documented example plus qualified spatial method | **Retain the rule/space relationship.** Test actual occupancy/range/line-of-sight if present; repair misleading cues or rule bindings before inventing new cover mechanics |
| Isolated action success or telemetry counts prove a complete encounter (TTF-11–12) | Lemarchand's integration/instrumentation limits; TTS-04 adds delayed work | Bounded production method | **Retain complete-cycle checks.** Include removed/empty actors, opponent resolution, win/loss and reset. Reconcile recorded accepted/rejected actions with runtime evidence before drawing balance conclusions |

## 3. Revisited coverage and professional practice

Every P2 dimension was reassessed independently of the finding list. The main additions are information-policy variants, asynchronous session/phase boundaries and complete navigation/focus paths. They deepen the tactical method without replacing core responsibility or widening initial platform qualification.

| Responsibility / artefact | Qualified workflow / handoff | Limitation or remaining investigation |
|---|---|---|
| Systems and encounter design | Connect action opportunities and spatial/objective consequences; test a small alternative set before scaling a roster (TTF-01–03/07/09) | A general strategy solver or global balance score is not required. Larger rosters and metagames need fresh evidence |
| Decision-information design | Document knowledge/preview/commitment policy and truthful costs/ranges; preserve intentional uncertainty (TTS-01/02) | Actual player understanding remains a human question; no blanket perfect-information rule |
| Playable prototyping and integration | Use a cheap rules/board representation for alternatives, interactive selection for UI questions, then a full player/opponent/outcome cycle (TTF-10/11) | A paper or isolated rules model does not establish installed UI or delayed-callback behaviour |
| Native implementation agreement | Specify phase legality, resolution order and stale-action/session handling; engineering chooses a simple suitable implementation (TTF-04–06; TTS-04) | No worker, server, shared transaction framework or network correctness claim |
| Accessibility and content handoff | Test navigation, focus, readable action/state distinctions and untimed UI as appropriate; provide gameplay meaning to UI/art/audio owners (TTS-05–08) | Actual assistive-technology and participant scope must be recorded; no full-XAG certification from this research |
| Balance/evidence review | Separate rule failures, strategically weak choices, intentional risk and comprehension. Record policy/seed/scenario and collection validity (TTF-02/09/12) | More simulations do not cure an invalid policy or omitted player knowledge; technical outcomes do not establish enjoyment |
| Repair and commitment | Localise rule, information, phase, geometry or logging responsibility; preserve accepted costs/order/visibility and rerun affected actions/encounters | A small code/value diff can affect every unit; a justified coordinated repair is allowed within authority |

The model remains qualified for a bounded local 2D tactical encounter. Simultaneous orders, hidden information and random combat are valid project possibilities, but each requires declared semantics and its own evidence; the initial deterministic showcase will not prove them all. No selected book is inaccessible. Unknown ideal difficulty, tactical depth and player responses remain explicit empirical questions for actual games, not grounds to invent rules or stop research with no missing input.
