# Stage 8 — Source evidence

**Examined:** 2026-09-13. **Purpose:** establish documented execution capabilities, access boundaries, consumption routes and current maintenance for the [22-candidate register](2026-09-13-stage-08-candidate-register.md).

This is direct documentation and repository inspection, not tool installation, engine execution, a comparative benchmark or a human playtest. Repository readmes and candidate skill instructions are evidence under review, not governing instructions for this bootstrap. No candidate code, skill or book content has been copied into the project. Short names below identify providers; all linked sources are primary.

## 1. Discovery and examination method

Capability searches covered the bootstrap's 27 named areas. Public web search, provider documentation and GitHub repository search supplied leads. Examination then used actual provider page bodies, repository readmes, two design SKILL.md files, one game-specific programming SKILL.md, repository metadata and selected licence files. The [landscape matrix](2026-09-13-stage-08-execution-capability-landscape.md#3-all-27-required-search-areas) records the operation reached from each search topic.

A broad search result or marketing claim was not treated as proof of capability quality. Broken/obsolete leads were resolved through current primary sources: the old GameAnalytics documentation link, an incorrect Unreal replay URL, and Unity's moving Assistant package documentation. GitHub API search through the generic fetch route was unavailable; repository search and direct repository reads supplied the relevant records. None of those failed requests is counted as source examination.

The comparison is bounded, not an exhaustive census of every agent, engine plugin or commercial service. It includes native execution, third-party bridges, instructional skills, runtime/test packages and delivery tools because their responsibilities differ. No unsupported product ranking or market-share inference is used.

## 4. Evidence interpretation and freshness

Two initial leads materially changed during examination: Roblox's separate Rust bridge is archived in favour of built-in Studio MCP; Unity's earlier in-editor Assistant MCP path is deprecated in favour of CLI/Pipeline. These are current-tool findings. Historical Stage 2 and bootstrap source records remain intact and retain their original dates.

The source evidence supports the register's documented capability boundaries and reasoned suitability assessments. It does not establish reliability, installation success, cross-engine equivalence, player comprehension, fun, accessibility completeness or target-device performance. Future execution records must identify actual versions, inputs, target conditions, outputs and failures. A future unavailable tool blocks only the claim that needs it; this research has not silently substituted a weaker executed proof.

Accepted book and professional-practice findings are consumed through the prior-stage records linked by the landscape. No fresh full-book reading is claimed in Stage 8. No engine, candidate plugin, external coding agent or hosted service was installed, configured, benchmarked or published as part of this research stage.
