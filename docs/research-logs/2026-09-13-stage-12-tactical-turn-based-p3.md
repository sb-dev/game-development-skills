## 3. Reconciliation and ownership

| Tension / overlap | Resolution |
|---|---|
| Formal economy versus the entire tactical experience | Use resource/strategy models for bounded questions. Information, positional constraints and observed human decisions may alter value; no numeric resource model is a complete account of tactics |
| Nystrom's reusable action versus a specific committed move | Distinguish the action type from an instance with actor/target/context. The pack requires truthful intent/commitment semantics, not an object-oriented implementation or a universal queue |
| Sequential initiative versus snapshot-based simultaneous effects | Declare the game rule first. Incidental storage order is not a valid hidden rule; intentional initiative is. Atomic visibility of a committed action does not require every unit to act simultaneously |
| Undo as a helpful tool versus intentional commitment/uncertainty | Treat selection cancellation, committed-action undo and full restart as different policies. Revealed information and consumed resources matter; P4 must challenge unrestricted undo and preview assumptions |
| Finite-state clarity versus whole-game state explosion | Use the smallest phase/action representation that clarifies the relevant transitions. Unit state, board occupancy and phase can interact without being flattened into a global graph or universal runtime |
| Fullerton's modularity/purity claims versus coupled gameplay | Reject guarantees of exact impact and single-purpose components. Preserve traceable dependencies and test affected combinations; a dual-purpose action can be intentional and interesting |
| Totten's prospect/refuge analogy versus turn-based threat | Translate through actual range, line-of-sight if present, action cost and information. Do not infer safety or pacing from architectural shape alone; no emotional universals |
| Adams/Dormans's solo economy ownership versus integrated production | Gameplay owns design choices but works with engineering, level, UI and evidence owners. The chapter's exclusive-ownership phrasing does not override the accepted handoff model |
| Fullerton/Lemarchand shared lineage | Merge general prototyping/evidence rules already in core. Keep Fullerton's decision-observation role and Lemarchand's full-cycle/instrumentation role; agreement is not independent validation |

**Core:** authority, rule/evidence records, adequate prototypes, human-claim boundaries, accessible task coverage, tooling and small repair. **Pack:** repeated action/opportunity, information/commitment, spatial-legality and phase-resolution analysis with derived cases. **Project:** turn order, actions/budgets, grids/ranges, randomness/knowledge policy, opponents, objectives and undo/retry rules. **Engineering:** native state/UI/pathfinding implementation, synchronisation, performance and transaction mechanisms. No universal command framework, replay protocol, tactical AI or engine is required by the books.

## 4. Provisional model and challenge handoff

The proposed workflow establishes the current decision state and information policy; enumerates legal actions with costs and spatial constraints; distinguishes preview/cancel/commit; specifies resulting phase/state changes; compares bounded alternatives and complete encounters; then diagnoses the responsible rule, presentation, execution or evidence fault and preserves accepted work during repair.

P4 must challenge the sufficiency of visible previews, deterministic tests, action-point arithmetic, scripted policies and state-pattern implementations. It must add current tactical examples with different uncertainty/recovery choices, decision/UI access guidance, opponent-knowledge constraints and actual execution-state considerations. No book establishes a universal amount of information, fair hit chance, ideal turn length or optimal number of actions. These are not missing-source blockers; they are bounded design/evidence questions.

Candidate evaluations extend core BC04 (coupled resource effect), BC08 (misleading evidence), BC09 (information channel), BC14 (removed target) and accepted state/outcome/reset responsibilities. They are not executed benchmarks. P5 will specify exact tactical cases after challenge research.
